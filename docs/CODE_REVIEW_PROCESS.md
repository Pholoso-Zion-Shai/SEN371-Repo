# Code Review Process

This project uses feature branches and pull requests for Milestone 3 code review evidence.

## Required workflow

1. Create a feature branch from `main` using a descriptive name such as `feat/jwt-auth` or `fix/booking-api`.
2. Make the change and run the relevant validation commands.
3. Push the feature branch to GitHub.
4. Open a pull request targeting `main`.
5. Add Person 4 and any other team members as reviewers.
6. Reviewers leave comments, identify risks, and suggest improvements using GitHub review tools.
7. The author addresses the comments and replies on the PR.
8. Person 4 submits a formal **Approve** review.
9. Merge only after approval.

## Evidence required for submission

- Screenshot of the feature branch and pull request showing the base and compare branches.
- Screenshot of review comments and suggested improvements.
- Screenshot showing the author response or resolved review comments.
- Screenshot showing Person 4's formal approval.
- PR URL and review URL included in the submission.

Screenshots must show real GitHub activity. This document is a process record and does not replace the GitHub review history.
